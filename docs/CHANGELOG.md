## 0.0.14 - 2026-09-28

### 新增

- 两份 changelog 以 `## Unreleased` 段承载尚未发布的条目，发布时改名成 `## X.Y.Z - YYYY-MM-DD` 并在最前补一个空的；`scripts/check-docs.mjs` 要求每份恰好一个、且在最新位置，并拿最新已发布段的版本去对那五个版本字段。

### 修复

- 混码的控制台输出改为按行分别解码：捕获里出现一处 OEM 字节，过去会把整块（包括同一批 npm 的 UTF-8 中文）一起送进代码页，回来的是一段"合法但说错话"的文本。
- 状态锁被毒化时不再丢掉失败报告：`fail()` 原先遇到 `Err` 直接返回，而那正是别的线程刚 panic、最需要告诉用户为什么没起来的时候；`snapshot()` 也不再回落成"还没启动"。
- 服务器在 token 请求上直接答 200、却又同时下发 cookie 时，那枚 cookie 会被带进交接，而不是把一个无 cookie 的 session 交给 dsh 窗口。
- 判断"这是一个 dsh，但它的会话你从这里进不去"只看 HTTP 401，不再额外要求响应体里出现那句英文提示串：本地化的 dsh 过去会掉进"端口被占用"，而那正是让启动它的人读成 bug 的说法。
- 装在 profile 的符号链接布局下（`$DSH_HOME/profiles/<名>/node_modules/.bin/dsh`）不再每次启动都报"有更新"：读已装版本时先跟完链接再往上找 `package.json`，找不到就什么也不提示。此前它找的是 `.bin` 的上一级、拿 `"0.0.0"` 顶替"不知道"，于是任何稳定版都比它新，对话框还显示你跑的是 0.0.0。
- 设了 `DSH_HOME` 而那个目录还不存在时，按字面使用它，不再静默回落到 `~/.dsh`：回落之后什么都找不到（没有 token、没有端口候选），而启动流程会顺手把回落那套目录建出来，在用户真正那套旁边多起一个没人要的服务器。
- 冷启动对同一批端口只走一遍：以前 `plan` 先自己扫一次日志端口，对话框端口列表又扫一次，而每个端口在 `check_port` 里本来就探两回。
- 启动失败那条路径和每次交给系统打开的链接，都不再留下没人回收的子进程（上一批只接了启动成功那一路）。
- 发布构建不再自带 WebView 检查器：两个窗口各自按 `DSH_SHELL_DEVTOOLS` 决定（调试构建总是开）。此前 `devtools` feature 一直开着，F12 与右键检查在生产构建里同样可用，而菜单项的门只挡住了菜单项。
- 安装包与四处记忆的设置文件都不再原地截断写：先落 `<name>.part` 再改名，读到的一定是写完整的文件；半截安装包出现在对话框打印的那个路径上的情况没有了。
- 检查更新的在途请求不再覆盖刚点下的"不再提醒"：候选是否已忽略按列表当前状态重算，而不是按发起检查时的快照。
- 连续两次交接不再让已经建好的 dsh 窗口留在隐藏状态：第二个调用者发现标签被占用时认作同一结果，不再把那次成功判为失败并复位交接状态。
- Unix 上由本外壳启动的服务退出后不再留下僵尸进程，有一个线程专门等待它。
- 缩放被 `DSH_SHELL_ZOOM` 钉住的那次运行不再改写记住的缩放值——钉住只在本次会话有效。
- 单实例的 accept 循环碰到不可恢复的错误时退出，而不是每轮一行 stderr 地空转到进程结束。
- 装上的版本无法归入任何已知通道时不再自动弹更新提醒：这种版本过去按"最不稳定"处理，于是任何通道都合格。

### 安全

- 注册在唯一带能力窗口上、页面却从不发的四个命令删掉了：`check_self_update`、`clear_dismissed`、`dismissed_versions`、`dismiss_path`。应用自定义命令不吃 capability 门，注册了就是那页 JS 能调的——其中两个还会真清数据、真吐路径。
- 交给系统默认程序打开的链接只接受 `http`、`https`、`mailto`：`explorer` 与 `open` 会执行命令行上点名的可执行文件，而 dsh 会往磁盘写文件，所以 `file:` 一类的链接是一次启动而非一次浏览。被拒绝的链接写进外壳日志。
- 来自发布接口的安装包文件名先验证是裸文件名才当路径用，Rust 与插件两条下载路径同修：带分隔符的名字既能写到缓存目录之外，又因为同一名字就是 `SHA256SUMS` 的键而自证校验通过。
- 插件在 Windows 上不再用 `runas` 动词交出安装包（那会静默提权），并改为把 argv 直接交给 `spawn` 而不是拼一条 shell 命令字符串。

### 维护

- 发布作业在算校验和之前先核对产物的名字集，而那份后缀表是从 `self_update.rs` 里读出来的——改了新前缀、某条 leg 空手而归，过去能一路绿到发布页，再让对话框打印一个没附上的文件名。
- 两份文档脚本共用的标题解析器现在有自己的测试（接在 `npm test` 里）：它认不出标题时的表现是双语检查对着两个空表通过，所以"守卫没生效"和"守卫通过"长得一模一样。
- 写明 Linux 的自动更新只覆盖 `.deb`：同一个发布也产 `.rpm` 与 `.AppImage`，那是发布说明里的手动路子，不是更新器漏选了什么。
- 已发布段标题的解析集中到 `scripts/changelog.mjs`，`check-docs.mjs` 与 `release-notes.mjs` 都走它。此前两者的正则本就不一致：换一种标题写法能让两本 changelog 同时解析为空，双语检查对着两个空表通过。
- `release-notes.mjs` 接受 `X.Y.Z-rc.N`（`release.yml` 本就切这种 tag 并标记为预发布），找不到对应段时打 `::warning::`，而不是安静地把发布正文留成一行 `Release X.Y.Z`。
- 单实例那条在 Windows 上必挂死的测试改为像外壳那样先把 accept 起在另一个线程上：`cargo test --lib` 现在能在 Windows 上跑完（它留下的僵尸进程也是上一轮 `LNK1104` 的原因）。
- 启动 token 的正则只编译一次，此前每次轮询都重新编译一遍——而 `wait_for_ui` 每 500 毫秒就要扫一次 256 KiB 的日志尾巴。
- 两份 README 的环境变量表按代码实际判定重写（判的是"有没有设置"而不是"是否非空"），补上此前没记的 `DSH_SHELL_RELEASES_API`、`DSH_BIN`、`DSH_NODE_BIN` 与插件那四个；AGENTS.md 的 Verify 清单补上漏掉的前端语法检查那条。

## 0.0.13 - 2026-09-24

### 新增

- 记住 dsh 窗口的大小与位置，下次启动放回原处；记忆中的位置只在当前某块显示器仍能看到它时才采用。

- 启动失败不再一律报「未就绪（进程已退出或超时）」：区分进程已退出、在监听但没写 token、握手未完成三种情况，后者报出本机 dsh 版本，并附上本次运行 stderr 的末尾几行。

## 0.0.11 - 2026-09-22

### 修复

- Windows 上更新 dsh 不再因 `\\?\` 前缀路径而失败：从启动器推导出的 npm 路径在进入命令行前会去掉该前缀，而 `cmd.exe` 无法执行这类路径。
- 更新失败的提示不再是一行乱码：子进程输出先按 UTF-8 解码，失败再按机器的 OEM 代码页解码；此前 Windows 自己的中文报错会变成替换字符。

## 0.0.5 - 2026-09-16

### 变更

- 外壳定位改为 dsh 的 desktop harness：Tauri 负责窗口、进程、启动与复用、会话交接、菜单/托盘/快捷键、更新、外链与故障恢复，页面归 dsh。
- 启动拆为两个窗口：`bootstrap` 承载进度、更新弹窗与失败信息，`dsh` 窗口只显示 dsh；启动期界面不可能覆盖在 dsh 上，这是结构保证而非约定。
- 会话交接移到 Rust：`resolve_session()` 完成并校验握手后返回干净地址与会话 cookie，启动 token 不进入页面 URL。
- 首次导航改为宿主发起，dsh 的 `SameSite=Strict` 保持不变。
- 菜单、托盘与快捷键：macOS 用原生系统菜单（含「编辑」菜单），Windows / Linux 用托盘菜单，快捷键仅在自身窗口获得焦点期间注册。
- 缩放改由 Rust 调用原生 `set_zoom`；开发者工具由 `devtools` feature 提供，release 构建默认不出现在菜单中。

### 移除

- 注入 dsh 页面的 `initialization_script`、401 文本嗅探、交接失败哨兵路径与页面内的 `Ctrl+R` 监听都已移除；外壳不再依赖 guest 的前端结构。

### 修复

- 交接不再停在 dsh 的 401 页面：会话 cookie 在建窗之前写入 cookie 存储并确认可读，并补上服务未给出的 `Domain`。
- `dsh` 窗口在页面加载完成前保持隐藏；加载超时回到 `bootstrap` 页面并说明原因。
- compat CI 断言示例输出的是不含 token 的干净地址，且该地址不带 cookie 时仍返回 401。
- Windows 构建不再因 `global-hotkey` 的 manager 而失败：manager 改放创建它的线程（`thread_local`），managed state 只保留纯数据。
- Linux 上不再出现「快捷键注册成功却不触发」：有 `DISPLAY` 时改用 X11 后端（XWayland），可用 `DSH_SHELL_WAYLAND=1` 退出。
- compat CI 增加 Windows 与 macOS 的 harness 编译检查；快捷键触发时记录日志。

## 0.0.3 - 2026-09-16

### 修复

- 交接失败后的重试改在 dsh origin 上进行，`SameSite=Strict` 的会话 cookie 因此能随请求发送，不再停在 401 文本上。

## 0.0.2 - 2026-09-16

### 修复

- 从桌面或文件管理器启动时，`node` / `npm` 改为按 dsh 自身的安装位置推导，不再取 `PATH` 上的第一个。
- 落到 dsh 鉴权页时不再黑屏：重新解析地址重试一次，仍失败则回到外壳页面并给出原因与下一步。

## 0.0.1 - 2026-09-15

### 新增

- 服务复用与启动：扫描 `3080`–`3129`，复用已在运行的 `dsh web`，否则在首个空闲端口以独立进程组启动。
- 启动 token 两步握手：从服务日志读取 token，`GET /?token=…` 换取会话 cookie 后复请并校验页面标记；握手不成立时，端口上的其他服务不会被误认为 dsh。
- 启动时更新检查：读取 npm 上 `@deepseek-ai/dsh` 的已发布版本，按正式版 / RC / Alpha 分栏展示，可安装后重启。
- 更新候选只取自稳定度不低于已装版本的通道。
- 「不再提示此版本」按版本记录于应用配置目录，仅抑制该版本。
- 站外链接交由系统默认程序打开。
- 打包 Windows 安装包、macOS dmg、deb、rpm 与 AppImage；release 关闭调试信息并启用 LTO 与体积优化。

### 安全

- Tauri capability 仅覆盖外壳自带的本地页面；交接后加载的 dsh 界面属远端源，不获得外壳 IPC 权限。
- 更新安装调用与已解析 `node` 同目录的 `npm`，不依赖 `PATH`。
